# TODO-09: 特記事項 (`special_notes`) の表示欠落解消と視認性強化

- **ステータス**: 完了（`CockpitView`・`ListView` 表示実装済み）
- **目的**: 公演の重要な補足条件（整理番号・入場順・声出しルール・物販注意・特典条件等）を管理者が登録した際、利用者が確実に見落とさず確認できるよう UI 表示を整備・強調する。

## 現状と課題

1. **`CockpitView.tsx` で `special_notes` 自体が描画されていない**:
   - `apps/web/src/components/CockpitView.tsx#L449` には `{/* レギュレーション・特記事項 */}` というコメントがあるが、実際に描画されているのは `photo`（撮可ルール）、`admission_bonus`（入場特典）、`ticket.prices`（チケット料金）のみであり、`session.special_notes` を表示する要素が存在しない。
   - そのため、管理画面（`AdminView.tsx`）や X/TimeTree 取込（`add.go` / `update.go` / `reconcile.go`）で `special_notes` を保存しても、メイン画面には表示されない状態になっている。
2. **視認性・強調度の整理**:
   - 既存データでも複数の注意点が ` / ` 結合された長いテキストになりうるため、単純な小文字テキストとして埋もれないよう、カード上の優先度・枠線・背景色（例: 警告／注意系アクセント）・改行表示を設計する必要がある。

## 検討・実装項目

1. **`CockpitView.tsx` への `special_notes` 専用カード／バナー追加**:
   - `session.special_notes` が非空のときに表示する視認性の高いブロックを追加する（アイコン付き・明確な見出し「特記事項」・コントラストのある枠線・長文でも読みやすい行間）。
   - `add.go` / `reconcile.go` が ` / ` で連結した項目がある場合、読みやすさに応じて箇条書き・改行表示にするかも検討する。
2. **`ListView.tsx` や一覧上のインジケータ検討**:
   - 一覧画面でも「特記事項あり」の要点またはバッジが視認できるか確認し、一覧性が崩れない範囲で補足表示を検討する。
3. **既存テストデータと実データの表示確認**:
   - 現在 `data/generated/schedule.json` や本番 GCS 上で `special_notes` が入っている公演（および空文字・`null` の公演）での表示崩れがないか確認する。
