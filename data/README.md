# データディレクトリ仕様書 (data/README.md)

本ディレクトリは、Ribbon Clock（taite-board）におけるイベント・タイムテーブル情報の収集・抽出・名寄せ・確定・配信パイプラインの全データを管理します。

ADR-0002（生スナップショット保存）および ADR-0007（ディレクトリ配置再編）に基づき、ライフサイクルごとに厳密に分離された5つのサブディレクトリで構成されます。

---

## 全体アーキテクチャとデータフロー

```text
+--------------+       +--------------+       +------------------+
| data/input/  | ----> |  data/raw/   | ----> | data/candidate/  |
| (Target URLs)|       | (Snapshots)  |       | (OCR & Parsed)   |
+--------------+       +--------------+       +------------------+
                                                        |
                                                        v
+------------------+       +-------------------------------------+
|  data/curated/   | ----> |          data/generated/            |
| (Entities/Rules) |       |   schedule.json (Production App)    |
+------------------+       +-------------------------------------+
```

---

## ディレクトリ構成と責務

### 1. `data/input/` (クローラー入力・巡回対象)
- **責務**: クローラーやスクレイパーが巡回・監視する対象のソース一覧を定義します。
- **主なファイル**:
  - `sources.json`: 監視対象のX（旧Twitter）アカウント、公式HP、カレンダーURLなどのメタデータ一覧。
  - `input_urls.txt`: アドホックに解析対象とするURLリスト。

### 2. `data/raw/` (外部取得の不変生スナップショット)
- **責務**: 外部APIやWebスクレイピング、画像ダウンロードによって取得された一次データを、加工せずそのまま保存します。
- **設計規約**:
  - **不変性（Immutability）**: 一度取得したデータは決して上書き・編集しません。
  - **実行ID分離**: `runs/<YYYYMMDD-HHMMSS>/` または `runs/<run-id>/` 配下にタイムスタンプ付きで分離保存します。
  - 不具合発生時やパーサー改善時に、外部へ再アクセスすることなく過去の取得時点を完全再現（Time Travel Debug）できます。
- **Git管理**: 大量のHTMLや画像ファイルが含まれるため、原則として `.gitignore` でリポジトリへの直接コミットを抑止します。

### 3. `data/candidate/` (抽出候補中間データ)
- **責務**: 生データから正規表現、LLM、OCRなどによって抽出されたスケジュール・タイムテーブルの暫定候補データを保持します。
- **主なファイル**:
  - `extracted_events.json`: 解析されたイベント日時、会場、出演枠、タイムテーブル枠、確信度スコア（Confidence Score）。
- **性質**: 未確定データであり、名寄せ処理やバリデーションの前段階となるキャッシュ領域です。

### 4. `data/curated/` (名寄せ辞書・手動補正マスター)
- **責務**: 人間（運用者）が責任を持って確定・管理するマスターデータと上書きルールです。
- **主なファイル**:
  - `entities.json`:
    - 主催者・出演グループ・メンバー・ライブハウス会場の正規IDと表記揺れエイリアス辞書。
    - 例: `Ayu Kagura`（`神楽あゆ`、`あゆちゃん`）などの名寄せマッピング。
  - `overrides.json`:
    - 自動抽出で拾いきれなかった出演時間の微修正、チケットURLの差し替え、中止・延期ステータスの強制上書きルール。
- **Git管理**: システムの信頼性の要となるため、**Git管理下に置きPRを通じて変更**します。

### 5. `data/generated/` (配信公開確定成果物)
- **責務**: Webフロントエンドやネイティブアプリが直接フェッチして利用する確定済みの公開JSON成果物です。
- **主なファイル**:
  - `schedule.json`: 公開用スケジュールデータ正本。
- **品質契約**:
  - ルートの `schema/schedule.schema.json`（JSON Schema Draft-07）に完全準拠し、`taite validate` によるスキーマ検査および整合性チェック（終了時刻が開演より後である等）を通過したファイルのみが配置されます。
  - Kubernetesコンテナビルド（Dockerfile）や GitHub Pages ビルド時にWebルートへ同期されます。

## 運用コマンド

### スケジュールの検証
```bash
# 生成された schedule.json がスキーマおよび整合性基準を満たしているか検証
./bin/taite validate --file data/generated/schedule.json
```

### スケジュールのビルドと成果物同期
```bash
# 最新の input / curated から確定データを生成・同期
./bin/taite build
./scripts/build.sh
```
