# ADR 0019: ポータル・ウォレットカードスタック UI アーキテクチャの採用 (Portal Wallet Card Stack Architecture)

## 状態
Accepted

## コンテキスト
`taite-board` は RiNCENT# および Dolly Kiss のマルチテナント基盤として各サブドメイン（`rincent.iorin.net`, `dollykiss.iorin.net`）で独立運用されている。
サービス全体の入り口となる共通ルートドメイン（`https://taite.iorin.net`）の新設に伴い、複数のグループを提示・選択するためのトップページ（ポータル UI）の設計が必要となった。

### 検討された選択肢
1. **音楽アプリ型二分割モデル（上部カルーセル ＋ 下部テキストリスト）**:
   Apple Music や Spotify 等の定番構成。上部に横スワイプカード、下部にコンパクトリストを置く。
   - *評価*: 汎用メディアアプリのテンプレート感が強く、画面を二分割することでアイドルの大判ポスターとしての没入感が失われる。また、グループ数が増えた際にカルーセルを横にめくる操作が煩わしい。
2. **表示切り替えトグル（大判カード ⇄ リスト）**:
   右上のトグルで表示形式を切り替える。
   - *評価*: モード切り替えは設計の妥協であり、画面の世界観を破壊するため不採用。
3. **ウォレット・カードスタックモデル（本採用）**:
   Apple Wallet のカード重なりに着想を得て、全グループをスクロールゼロの 1 画面内に縦方向のカードスタックとして配置する。

## 意思決定 (Decision)

以下の仕様を持つ「**ウォレット・カードスタックモデル (Wallet Card Stack)**」をトップページの標準 UI アーキテクチャとして採用する。

1. **空間階層と視覚的ヒエラルキー**:
   - 一番上のカード（最推しグループ）のみが大判写真（70〜80%）を露出させ、顔・衣装の特別感を誇示する。
   - 下に重なるカードは下部 20〜30% のみを露出させ、視認性の高い大判フォントでグループ名を配置する。顔が途中で切れる不格好さを排除し、巨大タイポグラフィバナーとして機能させる。
2. **単一の物理法則に基づくインタラクション**:
   - 「最前面のカードをタップ」: 1 タップで即座に対象グループのタイテ画面へ遷移。
   - 「後ろのカードをタップ」: 手前に浮上（Z軸）し、最前面へ上スライド（Slide-Over）して大判写真が展開。
   - 「外側タップ」: 元のスタック配置へ復帰。
3. **推しトップ固定機能 (Top Pinning)**:
   - 大判展開時の王冠アイコン押下により、`localStorage` に最優先グループを永続化。設定画面を介さず、ユーザーが推しを手札の最前列に据える行為を直感的に支援する。
4. **文字ノイズの完全排除**:
   - 説明用ボタンやリンク（「タイテを見る」等）は一切配置せず、大判写真面そのものをクリッカブルエリアとする。

## 影響・効果 (Consequences)

### ポジティブ
- **スクロール摩擦の完全排除**: アプリを開いた瞬間にスクロールゼロで全グループへ指が届く。
- **情緒と機能の高度な両立**: 推しの大判ショットによる愛着と、下部バナーによるグループ一覧性が矛盾なく成立する。
- **認知コストゼロ**: 毎回の開くたびに主役が勝手にすり替わるストレスがなく、安定した手札の定点として機能する。

### ネガティブ / トレードオフ
- **カード登録数の上限**: 1 画面内にスタックできるカード枚数は、下部バナーの視認性を考慮すると最大 5〜7 グループ程度が最適となる（それ以上の規模拡大時はカテゴリ分類やインデックス検索との連携を検討）。
