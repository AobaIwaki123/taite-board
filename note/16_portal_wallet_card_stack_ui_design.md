# ポータル・ウォレットカードスタック UI 設計書 (Portal Wallet Card Stack UI Design)

## 1. 背景と課題意識

マルチテナント基盤（`taite-board`）において、RiNCENT#、Dolly Kiss をはじめとする複数アイドルグループがサブドメイン（`*.iorin.net`）単位で独立稼働している。
本設計は、ルートドメイン（`https://taite.iorin.net`）および共通エントリーポイントにおける「ポータル（トップページ）」の UI/UX を定義する。

### 従来のカタログ型 UI におけるアンチパターンの排除
1. **音楽アプリ型二分割の拒絶**:
   画面上部に横カルーセル、下部にテキストリストを配置する汎用メディアアプリの構成は、アイドルのポスターやステージとしての没入感を損ない、業務ツール感を醸成するため採用しない。
2. **トグル切り替えによる世界観の破壊の禁止**:
   「リスト表示 / カード表示」などのトグルスイッチは設計側の妥協であり、画面のトーンや世界観を破壊するため排除する。
3. **「前回の閲覧履歴による主役すり替え」の認知コスト排除**:
   開くたびに画面の主役が前回の行動で変化する仕様は、「今何が表示されているか」を脳内で確認させる認知負荷を生む。ポータルはいつ開いても「複数のグループが秩序正しく共存する安定した定点」であるべきとする。
4. **スクロール摩擦の撲滅**:
   大判写真を縦に並べた場合、推しグループが下部に追いやられ、毎回スクロールを強要される。日課として開くアプリにおいてスクロール動作そのものを不要とし、「スクロールゼロで全グループに指が届く」構造を実現する。

## 2. コアコンセプト: ウォレット・カードスタック

Apple Wallet のカードスタックに着想を得て、アイドルアプリ特有の情緒（推しの特別感・大判写真の迫力）と、高い一覧性を両立させた独自構造を採用する。

```
+--------------------------------------------------------+
|                                                        |
|   【最推しグループ】（手札のトップ）                   |
|   メンバーの顔・衣装・大判ショットが 100% 全開         |
|                                                        |
|   RiNCENT#                                             |
+--------------------------------------------------------+
|                                                        |
|   【Dolly Kiss】（下部 25% のバナー領域）              |
|   ※顔は隠れており、大きくて見やすいフォントが鎮座     |
|   D O L L Y   K I S S                                  |
|                                                        |
+--------------------------------------------------------+
|                                                        |
|   【第3のグループ】（下部 25% のバナー領域）           |
|   ※顔は隠れており、大きくて見やすいフォントが鎮座     |
|   G R O U P   N A M E                                  |
|                                                        |
+--------------------------------------------------------+
```

### 空間構成の 3 原則
1. **最推しの顔を見せる特権（特別感の演出）**:
   手札の一番上のカードのみが、メンバーの顔・衣装・表情を含む大判写真（全体の 70〜80%）を堂々と表示する。
2. **下部カードの巨大タイポグラフィ（一覧性の確保）**:
   下に重なるカードは下部 20〜30% のみが露出し、大きくて見やすいフォントでグループ名を表示する。メンバーの顔が中途半端に見切れる不格好さを完全に防ぎ、美しいグループバナーとして機能させる。
3. **引き出した瞬間に顔が現れるドラマ性**:
   下のグループ名をタップすると、カードがせり上がって隠れていた大判写真（顔）が眼前に現れる。手札から引き出して初めて顔と対面するという情緒的な演出を提供する。

## 3. インタラクションモデル

本 UI は、認知負荷ゼロで直感的に操作できる「単一の物理法則」に基づいて設計される。

| 操作対象 | 状態 | タップ時の動作 |
|---|---|---|
| **最前面のカード** | 大判写真が全面露出 | **1 タップで即座に対象グループのタイテ画面へ遷移** |
| **後ろに隠れているカード** | 下部 20〜30% のみが露出 | **最前面へスムーズにせり上がり、大判写真が展開** |
| **画面外側（暗がり）** | カード展開中 | **元のスタック配置へ復帰** |

### トップ固定機能（推しを一番上に据える行為）
オタクにとって「推しを手札の一番上に置く」ことは認知負荷ではなく、愛着を満たす能動的な行為である。
- カードが大判展開された状態の右上に、控えめな王冠アイコンを配置する。
- タップすると「トップグループ」として `localStorage` に保存され、以降はアプリ起動時にそのグループが常に最前列（一番上）に君臨する。
- 設定画面や複雑なモーダルを介さず、カードとの対話の中で完結させる。

## 4. モーション・物理設計 (Motion Physics)

手前のカードを貫通するような安易なデジタルフェードを厳禁とし、物理的な手札の重なりを再現する「スライドオーバー（Slide-Over）」を採用する。

1. **手前への浮上 (Z-axis Lift)**:
   タップされた後ろのカードが、手前にわずかに拡大（`scale: 1.02`）し、シャドウ（`drop-shadow`）が濃く深くなることで、視覚的に手前へ浮き上がる。
2. **最前面への滑り込み (Slide-Over)**:
   浮き上がったカードが、そのまま上方向へスーッとスライド（所要時間: 200〜250ms, イージング: `cubic-bezier(0.16, 1, 0.3, 1)`）し、手前のカードを上から覆い隠すように最前面へ着地する。
3. **退避モーション**:
   外側タップ時は、浮上と逆の軌道で自然に元の位置（下部バナー）へ滑り落ちる。

---

## 5. 文字情報の極小化 (Zero Text Noise)

- 「タイテを見る」や「詳細を開く」といった説明的ボタン・リンクは一切配置しない。
- 大判写真面そのものが巨大なクリッカブルエリアであり、タップ時の触覚フィードバック（`active:scale-[0.98]`）により直感的に遷移を理解させる。
- 画面上のテキストは、ポスターの題字のように配置された「グループ名」のみに限定する。

---

## 6. ルーティングと環境自動判定

- **ポータル表示条件**:
  - ホスト名が `taite.iorin.net` の場合
  - サブドメインなし（`localhost` 等）かつクエリパラメータ `?group=` が指定されていない場合
- **タイテ画面への遷移先**:
  - 本番環境（`*.iorin.net`）: `https://<group_id>.iorin.net`
  - ローカル開発環境: `?group=<group_id>`
